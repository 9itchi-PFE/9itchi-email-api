# 9itchi Email API
Applications from the student's own Gmail: OAuth (send-only), AI letter draft, AI CV/offer match, send now or schedule, application tracking, quotas. Port 8085, DB `emails`.

## Conventions (shared by every 9itchi Go service)
- `handlers/` thin (validate, authorize, call service, JSON) -> `services/` all logic, returns `(T, *models.ApiError)` -> `repositories/` only Postgres, plain errors (`ErrNotFound`, `ErrConflict`). Error body `{"error": "..."}`.
- DB calls use `repositories.QueryTimeout`; multi-table writes `Store.WithTx`; never select bytea in list queries.
- Schema: add `migrations/NNNN_name.sql` (goose, embedded, runs at startup). Never edit a merged migration.
- Auth: `Authorization: Bearer` AES-GCM-wrapped HS256 JWT (claims `id`, `email`, `role`, `typ`, `exp`; access only). `/admin/*` = `RequireRole("admin")`. `/internal/*` = `x-api-key` (`INTERNAL_API_KEY`), blocked by nginx.
- Events: exchange `9itchi.events` (topic, routing key = event name), names in `core/events.go`; empty `RABBITMQ_URL` = `LogPublisher`.
- Env only, validated in `utils/config.go`. Common: `PORT`, `ENVIRONMENT`, `DATABASE_URL`, `ITCHI_SECRET_KEY`, `ITCHI_ENCRYPTION_KEY`, `INTERNAL_API_KEY`, `INTERNAL_API_KEY_REQUIRED`. Never log tokens, passwords, PII.
- Tests: `{resource}_test.go`, testify, func-field fakes (no testify/mock), success + error paths. Repo tests: `//go:build integration`, embedded Postgres.
- Check: `gofmt -l .; go build ./... && go vet ./... && go test ./...`; `go test -tags integration -count=1 ./repositories/...`; `golangci-lint run`.

## Routes
- Public: `GET /gmail/callback` (state = signed `gmail_state`, 10 min TTL).
- User: `GET /gmail/connect|status`, `DELETE /gmail/connection`; `POST /emails/draft`, `POST /emails`, `POST /emails/schedule`, `GET /emails`, `GET /emails/attachment-names`, `POST /emails/draft-from-link`, `/emails/:id` GET|PATCH (edit scheduled)|DELETE (cancel); `/applications` POST|GET, `GET /applications/allowance`, `/applications/match` POST|GET, `/applications/scores` POST|GET, `PATCH /applications/:id`, `POST /applications/:id/send`, `POST /applications/:id/follow-up/draft`, `POST /applications/:id/follow-up`; `POST /recruiters/search`, `POST /recruiters/company`, `GET /recruiters`, `GET /recruiters/allowance`, `POST /recruiters/:id/draft`.
- Admin: `GET /admin/users/:id/applications|gmail|sent-with-cv`, `GET /admin/prospects/stats` (pool counts, 30-day pool hit rates, 31 zero-filled UTC days of searches and provider credits).
- Internal: `DELETE /internal/users/:id`, `POST /internal/emails/:id/dispatch` (schedule-api), `GET /internal/emails/:id/context` (notification-api).

## Data, peers, events
- Tables: `gmail_connections` (tokens AES-GCM, `utils/crypto.go`), `emails`, `applications`, `job_matches`, `ai_drafts` (`source_url` for link/recruiter letters, `0010`), `recruiter_searches`, `recruiters` (`0009`; `contact_id`, `company_summary`, `matched_keywords`, `verified` in `0013`). Shared prospect pool (platform data, no `user_id`, not erased): `companies` (unique `domain`, `search_text` folded in Go, GIN full text), `contacts` (unique `lower(email)`, `opted_out`), `contact_lookups` (`(domain, provider)`, credits; overwritten, not a log) (`0013`), `provider_credits` (one row per provider spend, `0014`). `companies.logo_url` (`0015`, "" = unknown, <=500; an upsert without logo keeps the stored one). `recruiter_searches` stats columns `contacts_from_pool|contacts_found|companies_from_pool|companies_discovered` (`0014`, NULL = older or cached search). No bytea: CV fetched from resume-api at send time. `job_matches.origin` `analysis`|`score` (`0011`). `applications.follow_up_email_id|follow_up_sent_at` (`0012`). `emails.letter_filename` (stem, NULL = default name), `attach_letter` (default false: older rows send no letter), `letter_language` (NULL = from body) (`0016`). `emails.tracking_id` is text (tracker ids are 43-char base64url, `0017`). Latest `0017_tracking_id_text.sql`.
- Peers (`pkg/`, shared `pkg/httpx`): ai (`/ai/emails/draft`, `/ai/jobs/match`), resume (`/resumes/:id` (also title + contact name), `/internal/resumes/:id/pdf|original` (file name from `Content-Disposition`, `filename*` first), `POST /internal/letters/pdf` (cover letter PDF))|original`), job (`/jobs/:id`, `/internal/jobs/:id`, `POST /internal/offers/read`: 422 = unreadable, `POST /internal/companies/search`: error = no offer companies), tracker (`/internal/tracking`), schedule (`/internal/schedules`), payments (`/internal/quotas/:userId`), Google (`pkg/google`, `core.Mailer`), statistics (`pkg/statistics`, copy of ai-api: credits `hunter`/`apollo` reported, admin token wins over the env key), prospect sources (`pkg/recruiters`: `core.ContactFinder` map `Finders` = `website`, `hunter` (Domain Search), `apollo` (people search + match reveal), `fake`; `core.CompanyDiscoverer` map `Discoverers` = `hunter` (Discover, free), `fake`). `pkg/httpx` maps 404 to `ErrPeerNotFound`, 422 to `ErrPeerUnprocessable`.
- Publishes `email.sent`, `email.failed` (with `scheduled` flag), `application.first_sent`, `application.replied`. Consumes nothing.
- Env: `RABBITMQ_URL`, `AI_API_URL`, `RESUME_API_URL`, `JOB_API_URL`, `TRACKER_API_URL`, `SCHEDULE_API_URL`, `PAYMENTS_API_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GMAIL_REDIRECT_URL`, `CLIENT_URL`, `TRACKER_PUBLIC_URL`, `RECRUITER_CHAIN` (default `website,hunter,apollo`), `COMPANY_DISCOVERY` (default `hunter`, `none` = off) (unknown name fails startup; `fake` warns in production), `HUNTER_API_KEY`, `APOLLO_API_KEY` (comma separated = several accounts: round robin per call, a key answering 401/402/403/429 rests 1 h and the next is tried; `pkg/recruiters/keys.go`), `HUNTER_MONTHLY_CAP`, `APOLLO_MONTHLY_CAP` (default 50, credits per UTC month and per key), `STATISTICS_API_URL`.

## Domain rules
- Gmail scopes `gmail.send openid email` only; revocable; disabled unless both Google vars set. Revoked Gmail = 409 "reconnect gmail".
- Quotas from payments keys `emails_per_month`, `free_applications`, `ai_matches_per_month`, `ai_drafts_per_month`, `recruiter_searches_per_day`, `ai_scores_per_day` (Tunis day, `time.FixedZone("Africa/Tunis", 3600)`; absent/negative = unlimited, 0 = 402). Allowance modes: `plan` (9itchi CV, monthly), `original` (no subscription: `free_applications` over account life, sent with the imported file as is), `none`. Over limit = 402.
- One live application per offer: unique `(user_id, job_id)`, else 409. Recipient = job `apply_email` from job-api internal, else request `to`.
- Schedule window now+1 min to now+365 d; delivery via schedule-api -> `/internal/emails/:id/dispatch`; non-scheduled status or `scheduled_at` later than now+1 min = no-op.
- PATCH `/emails/:id`: scheduled only (else 409); `to` locked (409) when the offer has an `apply_email`; `attach_cv` false = no CV, true needs a `resume_id`; imported-file emails re-check the file (422). New time: new schedule task first (502 = no change), then the row, then the old task is cancelled (log only).
- Tracker down = send without pixel. Application flagged "CV attached" fails 502 if CV can't be attached.
- Attachments: CV under the name resume-api gives it (CV title; imported file keeps its extension; fallback `CV.pdf`), never renamed here (no `cv_filename` field). Cover letter PDF rendered by resume-api at delivery (`POST /internal/letters/pdf`, email subject/body, CV contact block, sender = Gmail address); `attach_letter` default true on `POST /emails`, `/emails/schedule`, `/applications`; failure = send failed 502 "the cover letter could not be attached". Name: `letter_filename` (cleaned: no folder/extension, letters/marks/digits/space `_-.()`, rest `_`, run of space/`_` = its first rune, <=80 runes), else `Lettre_de_motivation_<Name>` / `Cover_letter_<Name>` / `رسالة_تحفيزية_<Name>` (CV contact name, `_`-joined; unreadable = prefix alone). Same stem as the CV (case-insensitive) = 400. `language` fr|en|ar, absent = ar when the body is mostly Arabic else fr. PATCH `letter_filename: ""` = default name. Message > 25 MB = 422 (failed). Follow-ups attach nothing. `GET /emails/attachment-names?resume_id&language` -> `{cv_filename, letter_filename}` (404 unknown CV; other peer error = generic names). Never log names or file names.
- AI draft/match cached, not re-counted. Drafts: the newest `ai_drafts` row for the same `(user_id, job_id, language, tone, input_hash)` comes back (a lookup, not a unique constraint; `fresh` writes a new row). Matches: unique `(user_id, job_id, resume_id, language, input_hash)`.
- Link drafts: URL normalized (http(s), no fragment, no `utm_*`, max 2048). A `CLIENT_URL` `/offres/<uuid>` link is the normal job draft (`source` `9itchi`). Other links: plan checked first (0 = 402; month used up = last letter for that link, else 402), then job-api reads it (never stored there, never fetched from LinkedIn; 422 = "paste its text"); kept in `ai_drafts.source_url`.
- Recruiter Radar (pool first): `POST /recruiters/search {resume_id (required), goal (<=300), contract pfe|stage|alternance|cdi|cdd, keywords (<=10, <=40), country (alpha-2, default TN), city, contacts (1-10, default 5)}` -> `{search_id, cached, items, allowance, stats {companies_from_pool, companies_discovered, contacts_from_pool, contacts_found}}`; items add `verified`, `company_summary`, `matched_keywords`, `logo_url` (company of `contact_id`, http(s) only) (old rows: empty). No provider in the response (`recruiter_searches.provider` = `chain`). Same normalized query the same Tunis day = cached, not counted. 45 s budget. Terms = keywords + CV skills (max 10) + goal words (fr/en stop words out), accents folded. Companies: pool full text (country filter), then job-api offer companies (upserted, source `offer`), then discoverers only when fewer than `contacts`; companies the student got people of in 90 days are left out. People: pool (not opted out, checked/updated within 180 days), else the finders: free ones (website) first, then the capped ones least used this month first (share of cap, so Hunter and Apollo take turns), stopping at the first usable person; a finder without key, asked for the domain within 90 days (`contact_lookups`, 0 results included) or over its monthly cap is skipped; a provider error is skipped (not cached). Every answer goes to the pool. A company without domain is resolved by name (Hunter) or skipped; a finder that needs a domain (Apollo) gets its turn once it is known; a name the finder gives that is not the company's (`companyKey`: case, accents, punctuation, spaces and legal endings like Inc/SARL ignored) is dropped. 1 person per company first, at most 2; ranked recruiter titles, then founders/CEO/CTO of small (or unknown size) companies, then heads of tech, then verified, confidence. Website finder: robots.txt honored (error = site skipped), public hosts only (checked at dial: SSRF), 5 s/page, max 6 pages, 512 KB, same-domain mailboxes `rh`, `recrutement`, ... `contact`. `fake`: deterministic, `.example` only. `POST /recruiters/:id/draft` = spontaneous letter, cached/counted like link drafts under `source_url` `recruiter:<id>`; the recruiter title and company, the company summary and the search contract (read from `recruiter_searches.query`) reach the AI as `job_description`; the student's `goal` (else the search goal) goes as `goal`, the search `keywords` as `keywords` (hashed into the cache key only when present). CV text for the AI (`pkg/resume` `summaryText`): education with dates, experience/projects with bullets, certifications, languages, extra sections, skills; hidden entries out; cut at 7500 bytes. Never log names, emails or search terms (provider, counts, errors only).
- Recruiters at one company (offer link page): `POST /recruiters/company {company (required, <=120), domain (name, site or link, optional), goal (offer title, <=300)}` -> same shape as a search. Company from the pool by domain (else saved, source `link`) or by name (`companyKey` match, newest), else resolved by the finders (Hunter by name); people from the pool, else the finders chain (same skips, caps, pool writes); best 2 ranked like a search. Counts as 1 recruiter search (`recruiter_searches_per_day`, 402 like a search) only when someone is found; nobody = 404, not stored. Same company+domain+goal the same Tunis day = cached. The 90-day "already contacted" skip does not apply. Query stored `{company, domain, goal, contract, contacts}` (the recruiter draft reads goal).
- Follow-up (« relance »): only for an application waiting for an answer (`sent`/`opened`), 7 days (`FollowUpAfter`) after its email left (or after it was recorded, `self`), one per application (409 after), reset when the student applies again. Draft: ai-api `kind: follow_up` with the first email and the days since, cached/counted under `source_url` `followup:<application id>`, no CV read; subject forced to `Re: <first subject>`. Send: `via: gmail` only (422 otherwise), to the first email's recipient (never a typed address), no CV, plan mode only (402 « part of the subscription » without one; counted in `emails_per_month`).
- Match carries `keywords {matched, missing}` (offer order, computed by ai-api) and `keyword_coverage` 0-100, stored in `job_matches` (`0008`); rows made before read as empty lists and 0.
- Scores: `POST /applications/scores {resume_id, language, job_ids (1-10)}` -> `{items: [{job_id, score, level, reasons (<=3: strengths then gaps), status ok|cached|quota|error}], allowance: {limit, used}}`. CV read once; a `job_matches` row for the same input (score or analysis) = `cached`, free; else AI asked while `ai_scores_per_day` allows (rows `origin='score'` this Tunis day), else `quota`. Per-offer failures = `error`, never fail the list, no 402. `GET /applications/scores?resume_id&job_ids=a,b&language` = cached items only, no AI, no quota, no `allowance`.
- Hide advice: a `score` row on `/applications/match` has `origin: "score"` and empty `advice`. GET never asks. POST asks the full analysis and upgrades the row to `analysis` (counted now) when `ai_matches_per_month` allows; else returns the score without advice (no 402, not counted). Monthly analyses count `origin='analysis'` only.
